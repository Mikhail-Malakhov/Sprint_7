# Яндекс Самокат · API-тесты спринта 7

Набор из 29 тестов на Python, pytest и requests. Основное задание проверяет создание и авторизацию курьера, создание заказа и список заказов. Дополнительное задание проверяет удаление курьера, принятие заказа и поиск по трек-номеру. Параметризованный тест создания заказа отправляет `BLACK`, `GREY`, оба цвета и запрос без поля `color`.

## Запуск

Понадобятся Python 3.10+ и доступ к учебному стенду. Для другого стенда укажите полный адрес API с префиксом `/api/v1` в переменной `SCOOTER_API_URL`. [Документация учебного API](https://qa-scooter.praktikum-services.ru/docs/)

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -X utf8 -m pytest -v --alluredir=allure-results --clean-alluredir --allure-no-capture
```

Тесты создают свои данные. После теста фикстуры удаляют курьеров, отменяют заказы и завершают принятые заказы, если стенд отклоняет их отмену.

## Allure

[Готовый отчёт](allure-report/index.html) открывается в браузере. Для повторной генерации установите Java и Allure Report 2. [Установка Allure Report 2](https://allurereport.org/docs/v2/install-for-nodejs/)

```powershell
allure generate allure-results --clean --single-file -o allure-report
```

В репозиторий добавляются исходники и папка `allure-report/`. Сырые результаты прогона в `allure-results/` исключены через `.gitignore`.

## Наблюдения на учебном стенде

Перед автотестами были отправлены ручные запросы через Postman CLI. Отчёт содержит один полный прогон из 29 проверок. Прошли 27 проверок, одна упала, ещё одна прервалась из-за тайм-аута при создании курьера для проверки списка его заказов.

- Авторизация без поля `password` возвращает `504 Service unavailable`. Тест ожидает документированный `400` и JSON-сообщение о недостающих данных.
- Общий список заказов без фильтра по курьеру периодически отвечает `504 Service unavailable`. Набор проверяет и общий список, и наличие принятого заказа в списке конкретного курьера.
- При удалении курьера и принятии заказа пропуск ID в пути приводит к `404 Not Found.`. Документация для этих случаев приводит `400`. В тестах дополнительных ручек зафиксирован фактический ответ маршрутизатора.
- Создание курьера без `firstName` возвращает `201`. Обязательность логина и пароля проверяется отдельно.
